# 用户动态、关注、隐私与浏览足迹部署说明

## 需要创建的集合

在小程序当前云环境中创建以下集合：

| 集合 | 用途 | 客户端权限 |
| --- | --- | --- |
| `follows` | 关注关系 | 所有用户不可读写 |
| `browsingHistory` | 用户浏览足迹 | 所有用户不可读写 |

原有 `users`、`posts`、`mealRecords` 集合继续使用，不需要重建。所有社交数据均由 `userSocial` 云函数读写，云函数内部会根据当前调用者的 `OPENID` 校验身份和数据归属。

CloudBase 官方建议在云函数内部继续执行细粒度业务权限校验，因为云函数服务端具备数据库访问能力：

- https://docs.cloudbase.net/authentication-v2/auth/auth-control
- https://docs.cloudbase.net/database/security-rules

## 建议索引

`follows`：

- `followerId` 升序、`status` 升序
- `followingId` 升序、`status` 升序

`browsingHistory`：

- `userId` 升序
- 如果后续改成数据库直接排序，再增加 `userId` 升序、`visitedAt` 降序组合索引

索引可以在云开发控制台的数据库集合“索引管理”中创建。索引用于降低关注列表和历史记录增长后的查询延迟。

## 部署顺序

1. 创建 `follows` 和 `browsingHistory`，权限设为“所有用户不可读写”。
2. 部署 `userSocial` 云函数，选择“上传并部署：云端安装依赖”。
3. 重新部署 `ensureUser`，使公开资料查询遵守新的隐私设置。
4. 确认 `users`、`mealRecords`、`posts` 仍为客户端不可直接读写。
5. 使用两个不同微信号进行真机验收。

## 建议验收场景

1. A 关注 B，B 的粉丝数增加，A 的关注列表能看到 B。
2. A 取消关注 B，双方列表和数量恢复。
3. B 将资料设为“仅关注我的人可见”，未关注者看不到详细资料，关注者可以看到。
4. B 将动态设为“仅自己可见”，其他用户看不到动态卡片。
5. B 开启“展示打卡动态”后，允许范围内的用户可以看到打卡图片和菜名。
6. A 浏览帖子和 B 的主页后，可以在“我的—浏览足迹”查看并再次进入。
7. A 关闭“记录浏览足迹”后，新浏览不再入库，旧足迹仍可手动删除。
8. 长按单条足迹可以删除，点击“清空”可以删除自己的全部足迹。
9. 用户无法通过客户端直接读取其他人的足迹或修改关注关系。

## 当前动态数据说明

个人主页动态会读取：

- `posts` 中该用户已发布、非私密的帖子；
- `mealRecords` 中该用户的有效打卡记录。

当前社区首页仍有部分静态演示帖子，因此这些帖子暂时不会自动归入真实用户主页。等帖子发布功能正式写入 `posts` 集合后，个人动态会自动显示，无需再修改个人主页结构。
